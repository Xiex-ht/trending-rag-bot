# 实施记录：会自己更新知识的问答机器人

> Dify 1.17.1 + LangBot + QQ 官方机器人 · 全链路私有化部署复盘
> 本文记录架构决策、自动化管道实现、RAG 三轮消融实验数据与全部踩坑过程，与代码同仓演进。

## 一、目标与总体架构

验证一条**零公网服务器**的私有化 AI 助手落地路径：一台 Windows 笔记本 + Docker Desktop，机器人知识库每周自动更新，全程无人值守。

```
消息链路（实时问答）
QQ群/企微 ──WebSocket长连接──▶ LangBot(:5300) ──HTTP──▶ Dify 应用 API ──▶ qwen3.5-plus
                                  │                        ▲
                                  │ 机器人/流水线解耦        │ RAG 检索
                                  ▼                        │
                            多端复用同一流水线          Weaviate 向量库

数据链路（周更知识管道）
Windows 任务计划(每周一 09:00)
   ▼
每周爬取.bat（ASCII 调度层）
   ├─▶ 爬虫：GitHub 周榜 Top10 + README 摘要 → 结构化 Markdown ×11
   └─▶ kb 同步：对账式更新 Dify 知识库（新增/同名覆盖/过时清理）
```

## 二、部署与网络适配

本机网络环境对 GitHub/Docker Hub 间歇性不可达（DNS 污染、直连超时），形成一套通用解法：

1. **镜像可达通道探测**：直连 → 官方国内源 → 公共加速站逐一测活；
2. **拉取与声明解耦**：从可用源拉取后 `docker tag` 恢复 compose 声明的镜像名，配置文件不用改；
3. 代码类下载走加速代理 zip（仓库 zip 同样保留 `--proxy` 参数位便于日后切 Clash）。

部署形态：Dify 官方 compose（15 服务）；LangBot compose 起主服务+插件运行时，其 Box 沙箱因 Windows 盘符冒号挂载问题以 `BOX__ENABLED=false` 降级关闭（不影响聊天链路）。

## 三、知识库自动化管道

### 3.1 爬虫（crawler/爬虫.py）

- `requests + BeautifulSoup` 解析 `github.com/trending?since=weekly`（服务端渲染，无需 JS）；
- GitHub REST 补 topics/默认分支；`raw.githubusercontent.com` 抓 README，多分支×多文件名 7 组合降级，实测 10/10 成功；
- README 清洗：去图片徽章/代码块/标题符号，压缩为 ~500 字摘要段；
- 产出 11 个 UTF-8 Markdown：每项目含「排名信息句 + 基本信息表 + 项目简介 + README 摘要」，另有汇总（排名速查 + 明细表 + 统计）。

### 3.2 同步（crawler/dify_kb_sync.py）——对账式，幂等

```
本地文件清单 vs 知识库文档列表
  新增      → create-by-file 上传
  同名已存在 → 删除旧文档后重传（防重复入库）
  本地已消失 → 删除（榜单每周换血，过时文档必须清理，防污染检索）
```

踩坑：批量删除端点 `DELETE /datasets/{id}/documents` 返回 405——官方实为**单文档**端点 `.../documents/{doc_id}`，改逐个删除后实测 11/11 成功。

### 3.3 调度（Windows 任务计划程序）

- 每周一 09:00；`StartWhenAvailable` 错过补跑；电池模式可运行；
- "不管用户是否登录"模式需验证账户密码（PIN 无效），改用"仅登录时运行"+补跑等效达成；
- **cmd 中文编码架构解**：中文目录/中文文件名在 bat 中被 GBK/UTF-8 反复转码（曾误执行同目录另一脚本）。终解：bat 只引用 ASCII 文件名，中间启动器在 Python 运行时按内容标记定位真实脚本——编码问题下沉到无此问题的层面解决。

## 四、Prompt 工程：双人格路由

需求：技术问答=专业助手，闲聊/身份=小说角色，互不污染。

失败教训与定稿结构：
1. **语气必须绑定在角色内部**——写在公共区会被角色 A 吃掉全部话语权；
2. 路由条件要给**判定优先级**（拿不准时技术/知识库范畴一律走技术角色）；
3. **正反对照示例**是切换类指令最有效的约束；
4. 拒答约束（"查不到就直说没有"）实测生效：拒答类问题零编造；
5. 混合思考模型（Qwen3+/DeepSeek-R 类）的推理通道独立于正文，提示词管不住 think 泄漏，须在模型参数关 `enable_thinking` 或换非思考模型。

验证：42 题技术评测全程无人设腔调泄漏；身份题正常回到角色模式。

## 五、RAG 三轮消融实验（核心数据）

评测集：42 题（事实检索 24 / 内容归纳 10 / 汇总统计 2 / 比较推理 2 / 拒答对照 2），带标准答案与出处文档；每轮单变量，重跑同卷。

| 轮次 | 配置 | 人工复核准确率 | 说明 |
|---|---|---|---|
| 基线 | TopK3 · 纯向量检索 | 76% (32/42) | 排名类 5 题全错 |
| 实验一 | +混合检索 · TopK5 | 93% (39/42) | 修复 7/10 排名错题 |
| 实验二 | +面向检索的文档改写 | 97.6% (41/42) | 表格边界盲区清零 |

（机器初判关键词命中率全程大幅低估：43%~50% vs 人工 76%~97.6%，见 §六-2）

### 关键发现

1. **表格是向量检索的结构性盲区**：Markdown 大表被定长分段切碎后，行间语义高度相似、"排名数字"不携带语义信号——问"第 1 名"召回的是第 5/7 行。修复路径：混合检索救回 7/10；在爬虫模板中把表格信息**额外转写为自然语言排名句**（"本周第 N 名是 X 项目"）入库后清零。核心原则：**知识文档的形态要贴着提问方式设计（writing for retrieval）**。
2. **部分召回诱发过度自信**：某轮"Star 总量最高"基于不完整召回自信答错（漏看一行）——答非所问先看检索日志归因（没检到/检错段/模型没用好），不同归因对应不同动作。
3. **评测集需要维护**：重爬后 star 数刷新，标准答案随之过期；拒答题在关键词判卷下天然失效，需规则初判+人工复核分层。

## 六、其他排障速记

1. Weaviate 镜像 `cr.weaviate.io` 域名被引擎丢弃、回退 Docker Hub 且 Hub 被 DNS 污染 → §二 的 tag 方案；
2. 关键词自动判卷四类系统性失真（千分位逗号、同义措辞、归纳长答、拒答题）→ 机器分仅作初筛；
3. `Workflow not published` 400 → Dify 应用必须发布后才对外提供 API；
4. LangBot 容器访问宿主机 Dify：`http://host.docker.internal/v1`；
5. IDE 报 requests/bs4 未解析但运行正常 → IDE 解释器与命令行环境不一致，纯静态分析误报。
